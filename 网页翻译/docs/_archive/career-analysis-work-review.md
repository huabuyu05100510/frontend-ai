## 3. 真正的简历缺口（10 年专家视角）

### 3.1 缺口 1：ML + 前端深度交叉（核心缺口）
- **现状**：讯飞做过 AI 能力**集成**（调 API、做 SaaS），但没做过 AI 能力**深度内嵌**（在浏览器跑模型 / attention 矩阵投影 / 向量检索前端化）
- **为什么是缺口**：2024-2026 年前端行业最热方向，会的人极少
- **代表作应该填这个缺口**

### 3.2 缺口 2：开源 / 公开技术影响
- **现状**：work.md 无任何开源项目 / 演讲 / 论文 / 技术博客记录
- **为什么是缺口**：10 年专家的简历没有公开技术产出，**面试官无法验证你的深度** — 公司内工作都受 NDA 保护
- **代表作必须开源**

### 3.3 缺口 3：AI Agent / LLM 工作流深度
- **现状**：滴滴进行中（行中导游 / 图搜地点），但**未沉淀为可讲的技术深度**
- **为什么是机会点**：当前行业最热方向，且你正在做 — 有 IP 主导权
- **需要把"在做"变成"做透 + 讲清楚"**

### 3.4 次要缺口
- 跨端工程化（小程序/H5/PC）— 已有但未突出
- 大规模数据可视化 — 未涉及
- 实时音视频 — 未涉及

## 4. 关键发现：现有「网页翻译」项目方向选错

### 4.1 事实对比

| 维度 | 讯飞网页翻译（5 年前） | 当前业余项目 |
|---|---|---|
| 语种 | 123 语种互译 | 中文 ↔ 英文为主 |
| 文档格式 | 23 种 | HTML 单一 |
| 文件大小 | 最大 1G | 段落级 |
| 商业化 | 盈利 SaaS 平台 | 个人 demo |
| 工程规模 | 部门重点项目 | 单人项目 |

### 4.2 面试官视角
看到简历：
> 「讯飞做过 123 语种商业翻译平台，现在业余做个 20 语种的网页翻译插件」

**第一反应**：
- ❌ "这是降级" — 用业余项目证明已经证明过的能力
- ❌ "没有成长" — 5 年后做更小规模的同类型项目
- ❌ "稀缺性不足" — 翻译能力已经饱和

### 4.3 结论
**现有「网页翻译」项目作为代表作定位失败**。
不是工程质量问题，是**方向问题** — 翻译对你不是稀缺能力。

## 5. 真正的代表作候选

### 候选 1：滴滴「AI 图搜地点」开源复刻（强烈推荐）

**原始工作**：
> 根据图片或文字 query 信息搜索类似地点，类小红书打卡搜索

**为什么是真代表作**：
| 维度 | 评估 |
|---|---|
| ML + 前端深度交叉 | ✅ 跨模态检索（图→地点），CLIP embedding + 向量索引 |
| AI Agent 能力 | ✅ 当前行业最热方向 |
| 稀缺性 | ✅ 会做 CRUD SaaS 的多，会做跨模态检索前端的极少 |
| IP 主导权 | ⚠️ 滴滴在职，需做「个人版开源复刻」用公开数据 |
| 可演示 | ✅ demo 一放出来面试官就懂 |

**风险**：
- IP 归属：滴滴在职期间做相关开源有竞业风险，**必须用公开数据 + 不同实现**
- 工作量：6-8 周

### 候选 2：滴滴「行中导游」开源复刻

**原始工作**：
> 基于旅行路线设计景点讲解 + 生成语音 + AI 博客

**为什么是代表作**：
| 维度 | 评估 |
|---|---|
| AI Agent 工作流 | ✅ 路线规划 + 讲解生成 + TTS 串接 |
| 流式体验 | ✅ 语音/讲解是天然流式场景 |
| 可开源复刻 | ✅ 个人版用公开 LLM + TTS |
| ML + 前端深度 | ⚠️ 偏 LLM 编排，前端深度不如图搜 |
| 稀缺性 | ⚠️ 中等 — AI Agent 类项目已经不少 |

**比候选 1 稍弱**：前端深度不够，且 AI Agent 赛道已经卷

### 候选 3：性能工程方法论 + 工具链开源

**原始工作**（阿里）：
> FCP<1000ms、LCP<2000ms、CLS<0.02、INP<200ms

**为什么是代表作**：
| 维度 | 评估 |
|---|---|
| 数据可量化 | ✅ 有具体 Web Vitals 数据 |
| 性能工程稀缺性 | ✅ 中等 |
| 是否新东西 | ❌ 过往工作，不是新产出 |
| 开源可行性 | ⚠️ 需要抽象成通用工具链 |

**问题**：是过往工作，**包装成"方法论 + 工具"开源工作量大**

## 7. 现有「网页翻译」项目的重新定位

**不要再当代表作做。** 改为以下两种定位之一：

### 定位 A：公开 Portfolio 样本（推荐）
- 讯飞/阿里/滴滴工作受 NDA 保护，**代码不能开源**
- 翻译项目是**唯一能放 GitHub 给面试官看的代码**
- 目标：**证明工程纪律**（TDD / e2e / 可观测 / 文档完整）
- **不做深度创新，做完整度**
- 工期：2-3 周收尾

### 定位 B：词级对齐的载体
- 翻译是**承载 ML+前端深度的壳子**
- 真正价值是「词级对齐可视化」
- 工期：5-7 周（详见 `docs/local-translation-tech-plan-V1.md`）

### ❌ 不要做的定位
- "比沉浸式翻译更好的翻译插件" — 讯飞已经做过了
- "性能极致的翻译" — 阿里已经证明过了
- "标签保留率业界第一" — 小差异，不构成代表作

## 8. 推荐策略：双项目并行

### 项目 1：网页翻译（公开 portfolio，2-3 周）
- **目标**：工程纪律样本，开源
- 范围：现有功能做完整 + benchmark + 可观测 + 文档
- **不做 ML 创新**
- 放 GitHub，简历附链接

### 项目 2：AI 图搜地点开源复刻（真代表作，6-8 周）
- **目标**：ML + 前端深度交叉代表作
- 技术栈：embedding（CLIP / 中文版）+ 向量库（HNSW）+ 前端可视化
- 数据：公开景点图数据集
- **这才是 10 年专家的代表作**

### 为什么并行
- 翻译项目收尾快（2-3 周），不占太多精力
- 图搜项目是真主力，需要 All in
- 翻译项目的工程纪律（TDD/e2e）可以直接迁移到图搜项目
- 两个项目互补：一个证明工程，一个证明深度
