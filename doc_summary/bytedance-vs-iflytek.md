# 字节 vs 讯飞：语音前端专家布局对照

> 同一个"语音前端专家"头衔，两家公司写的是两套完全不同的代码。
> 本文档对照 2026-07-01 两次架构推演，作为定位参考。

---

## 一、基因对照

| 维度 | 字节专家（火山引擎/豆包） | 讯飞专家（企业/行业线） |
|---|---|---|
| 优化目标 | 留存·CTR·DAU | 准确率·SLA·合规 |
| 网络假设 | 永远在线 | 永远可能离线 |
| 端侧地位 | 云的降级 | 一等公民 |
| 设备形态 | 浏览器/手机为主 | 10+ 异构端（车/家电/办公本/听辅/录音笔） |
| 部署模式 | SaaS / 公有云 | 私有化 + 信创 + 公有云 |
| 差异化 IP | 状态机·RTC·可观测 | 方言·多模态·端侧·合规 |
| 客户语言 | "用户·转化·漏斗" | "客户·精度·举证·国产化" |
| 实验文化 | A/B 一切 | 确定性优先 |

## 三、我会坚决不做的事（对照）

| 字节不做 | 讯飞不做 |
|---|---|
| 不在 TS 里写 DSP | 不假设网络可用 |
| 不做"通用 SDK" | 不卷 A/B 实验 |
| 不在没 SLO 定义前写代码 | 不依赖现代浏览器 |
| 不把可观测性放最后 | 不做单一"通用 SDK" |
| 不依赖浏览器 `echoCancellation` | 不把端侧当云的降级 |

| 字节版 | 讯飞版 |

## 六、核心洞察

1. **字节的 IP 在 Web 工程化与状态机**——因为消费互联网前端是主战场
2. **讯飞的 IP 在跨芯片编译与行业纵深**——因为 B/G 端付费理由是"在我家跑得起来"
3. **同样头衔，两套代码**——优化方向完全不同
4. **选择雇主 = 选择 IP 方向**——字节卷规模，讯飞卷纵深

## 七、一句话定位对照

**字节版**：
> 做语音交互平台，N1 一份 C++ DSP 编译到 Web/Electron/小程序，N3 一套状态机+协议+可观测，向上孵化 5 条产品线 SDK。

**讯飞企业版**：
> 做语音智能平台，N1 一份 C++ ASR 编译到国产 5 类芯片+信创 OS+浏览器+端侧 RTOS，N3 带方言路由+离在线+多模态+合规举证四件套，向上孵化 8 大行业 SDK。
