### 一个真实的语音交互场景

让我们从一个最简单的语音助手场景说起：

```
用户：点击麦克风按钮
系统：开始录音，显示"正在听..."
```

- **播放控制**：如何精确控制播放、打断、暂停？

## 第一章：浏览器音频 API - 从播放到实时处理

### 1.1 为什么 `<audio>` 标签不够用？

如果你只做过音频播放（比如播放音乐、播客），`<audio>` 标签完全够用：

```html
<audio src="music.mp3" controls></audio>
```

但当你想做实时语音交互时，问题来了：

#### 问题 1：无法获取原始音频数据

```html
<!-- 你能做的只有播放 -->
<audio src="recording.mp3"></audio>

<!-- 你做不到的：
     - 获取麦克风输入
     - 实时分析音频波形
     - 在发送前处理音频（降噪、压缩）
-->
```

这就像你想做一道菜（处理音频），但只能买成品菜（完整音频文件），买不到原材料（原始音频数据）。

#### 问题 2：延迟太高

`<audio>` 标签的缓冲策略是为播放优化的：预加载足够多的数据，确保播放流畅。这对听音乐是优点，但对实时通话是灾难。

**实际体验**：
- 用户说"你好"
- 系统过了 500ms 才收到音频数据
- 再经过网络传输、识别、生成回复
- 用户听到回复时已经过了 2-3 秒

在实时对话中，超过 200ms 的延迟就会明显感觉到"不跟手"。

#### 问题 3：无法控制播放细节

当你需要：
- 精确控制播放进度（跳转到某毫秒）
- 同时播放多个音轨（背景音乐 + AI语音）
- 实时调整音量、速度
- 可视化音频波形

`<audio>` 标签都无能为力。

### 1.2 Web Audio API - 浏览器的音频工作站

Web Audio API 是浏览器提供的专业音频处理框架。想象它像一个音频工作站：

```
┌─────────────────────────────────────────────┐
│            AudioContext（音频上下文）          │
│                                             │
│  麦克风 → 音频源节点 → 处理节点 → 扬声器       │
│   🎤         📊          🔧         🔊      │
│                                             │
│  可以添加多个处理节点：                        │
│  - 增益节点（调节音量）                       │
│  - 滤波器节点（降噪）                         │
│  - 分析节点（可视化波形）                      │
└─────────────────────────────────────────────┘
```

**基本使用**：

```javascript
// 1. 创建音频上下文（想象成打开音频工作站）
const audioContext = new AudioContext();

// 2. 获取麦克风
const stream = await navigator.mediaDevices.getUserMedia({ audio: true });

// 3. 创建音频源节点（把麦克风信号接入工作站）
const source = audioContext.createMediaStreamSource(stream);

// 4. 创建音频目标节点（连接扬声器）
const destination = audioContext.destination;

// 5. 连接：麦克风 → 扬声器
source.connect(destination);

// 现在你说话，扬声器会播放你的声音（可能有回音，实际使用要小心）
```

### 1.3 ScriptProcessorNode - 第一次尝试实时处理

Web Audio API 提供的第一个实时处理方案是 `ScriptProcessorNode`：

```javascript
const audioContext = new AudioContext();
const stream = await navigator.mediaDevices.getUserMedia({ audio: true });
const source = audioContext.createMediaStreamSource(stream);

// 创建处理器节点
// 参数：缓冲区大小(4096个采样)、输入声道数(1)、输出声道数(1)
const processor = audioContext.createScriptProcessor(4096, 1, 1);

// 每当缓冲区填满，触发一次回调
processor.onaudioprocess = (event) => {
  // 获取输入数据（Float32数组，范围 -1.0 到 1.0）
  const inputData = event.inputBuffer.getChannelData(0);

  // 这里可以做任何处理：
  // - 计算音量
  // - 检测是否有人说话
  // - 发送到服务器

  console.log('收到音频数据:', inputData.length, '个采样');
  console.log('当前音量:', calculateVolume(inputData));
};

// 连接节点
source.connect(processor);
processor.connect(audioContext.destination);
```

**看起来很完美？但有个致命问题。**

### 1.4 主线程阻塞问题

`ScriptProcessorNode` 的回调函数运行在**主线程**。这意味着：

```
主线程要处理的事情：
├─ UI 渲染（HTML、CSS）
├─ JavaScript 执行（你的代码）
├─ 事件处理（点击、滚动）
├─ 网络请求
└─ 音频处理回调 ← 也在这里！
```

**问题演示**：

```javascript
processor.onaudioprocess = (event) => {
  // 假设这里做复杂的音频处理
  const result = heavyAudioProcessing(event.inputBuffer); // 耗时 30ms

  // 在这 30ms 内，主线程被阻塞：
  // - 用户点击按钮没反应
  // - 页面滚动卡顿
  // - 动画停顿
};
```

**实测数据**：

| 场景 | 主线程负载 | 音频丢帧率 | 用户体验 |
|------|-----------|-----------|---------|
| 单纯音频处理 | 15% | 0% | 流畅 |
| + React 重渲染 | 45% | 2% | 偶尔卡顿 |
| + 网络请求 | 60% | 5% | 明显卡顿 |
| + 复杂动画 | 85% | 15% | 严重卡顿 |

### 1.5 AudioWorklet - 线程隔离的解决方案

为了解决主线程阻塞问题，浏览器引入了 `AudioWorklet`。它的核心思想很简单：

**把音频处理放到独立的线程，与主线程完全隔离。**

```
┌──────────────────────────┐
│      主线程               │
│  - UI 渲染               │
│  - 业务逻辑               │
│  - 网络请求               │
│  - 不受音频处理影响        │
└──────────────────────────┘
         ↕ (通过 MessagePort 通信)
┌──────────────────────────┐
│   Audio Worklet 线程      │
│  - 音频处理               │
│  - 独立运行               │
│  - 高优先级               │
└──────────────────────────┘
```

**实现代码**：

```javascript
// ========== 主线程代码 ==========

const audioContext = new AudioContext();

// 加载 Worklet 处理器（一个独立的 JS 文件）
await audioContext.audioWorklet.addModule('my-processor.js');

// 创建 Worklet 节点
const workletNode = new AudioWorkletNode(audioContext, 'my-processor');

// 接收来自 Worklet 线程的消息
workletNode.port.onmessage = (event) => {
  const { type, data } = event.data;

  if (type === 'audio-chunk') {
    // 收到处理好的音频数据
    sendToServer(data);
  } else if (type === 'volume') {
    // 收到音量数据，更新 UI
    updateVolumeIndicator(data);
  }
};

// 获取麦克风
const stream = await navigator.mediaDevices.getUserMedia({ audio: true });
const source = audioContext.createMediaStreamSource(stream);

// 连接：麦克风 → Worklet → 扬声器
source.connect(workletNode);
workletNode.connect(audioContext.destination);
```

```javascript
// ========== my-processor.js（独立线程运行）==========

class MyProcessor extends AudioWorkletProcessor {
  // 构造函数
  constructor() {
    super();
    this.volume = 0;
  }

  // 每次收到音频数据都会调用这个方法
  // inputs: 输入音频数据
  // outputs: 输出音频数据
  // parameters: 参数（可以动态调整）
  process(inputs, outputs, parameters) {
    // 获取第一个输入的第一个声道
    const input = inputs[0][0];

    if (input) {
      // 计算音量（RMS）
      let sum = 0;
      for (let i = 0; i < input.length; i++) {
        sum += input[i] * input[i];
      }
      this.volume = Math.sqrt(sum / input.length);

      // 发送音量到主线程
      this.port.postMessage({
        type: 'volume',
        data: this.volume
      });

      // 发送音频数据到主线程
      // 注意：这里会拷贝数据，后面会讲如何优化
      this.port.postMessage({
        type: 'audio-chunk',
        data: input.slice() // 拷贝一份
      });
    }

    // 返回 true 表示处理器继续运行
    return true;
  }
}

// 注册处理器
registerProcessor('my-processor', MyProcessor);
```

**性能对比**：

| 指标 | ScriptProcessorNode | AudioWorklet |
|------|---------------------|--------------|
| 运行线程 | 主线程 | 独立线程 |
| 影响UI | 会阻塞 | 不影响 |
| 丢帧率(高负载) | 15% | <0.1% |
| 延迟稳定性 | 不稳定 | 稳定 |

### 1.6 音频数据格式详解

在 Web Audio API 中，音频数据是什么格式？

#### PCM - 原始音频数据

PCM (Pulse Code Modulation) 是最原始的音频数据格式。想象你对着麦克风说话：

```
声波（模拟信号）
    ↓ 采样（每秒采样若干次）
离散的数值（数字信号）
```

#### 关键参数

```javascript
// 创建 AudioContext 时指定采样率
const audioContext = new AudioContext({
  sampleRate: 16000  // 每秒采样 16000 次
});
```

**采样率 (Sample Rate)**：
- 8000 Hz：电话音质，够语音识别用
- 16000 Hz：宽带语音，常用
- 44100 Hz：CD 音质
- 48000 Hz：专业音频

**声道数 (Channel Count)**：
- 1：单声道（语音识别常用）
- 2：立体声（音乐播放常用）

**位深度 (Bit Depth)**：
- 16-bit：常用，范围 -32768 到 32767
- 32-bit float：Web Audio API 内部格式，范围 -1.0 到 1.0

#### 数据大小计算

```javascript
// 1 秒钟的音频数据大小
const sampleRate = 16000;  // 采样率
const channels = 1;        // 单声道
const bitDepth = 16;       // 16位

const bytesPerSecond = sampleRate * channels * (bitDepth / 8);
// = 16000 * 1 * 2 = 32000 字节 = 31.25 KB
```

**实际应用**：

```javascript
// Web Audio API 返回的是 Float32Array
const inputData = event.inputBuffer.getChannelData(0);
// inputData 的值范围是 -1.0 到 1.0

// 但很多服务器/ASR 引擎期望 Int16 格式
// 需要转换：
function float32ToInt16(float32Array) {
  const int16Array = new Int16Array(float32Array.length);
  for (let i = 0; i < float32Array.length; i++) {
    // 将 -1.0~1.0 映射到 -32768~32767
    const s = Math.max(-1, Math.min(1, float32Array[i]));
    int16Array[i] = s < 0 ? s * 0x8000 : s * 0x7FFF;
  }
  return int16Array;
}
```

## 第二章：线程间通信 - 数据传输的艺术

### 2.1 为什么数据传输是个问题？

上一章我们提到，AudioWorklet 处理音频后需要把数据传给主线程。最简单的方式是：

```javascript
// Worklet 线程
this.port.postMessage({
  type: 'audio-chunk',
  data: audioData  // Float32Array
});

// 主线程
workletNode.port.onmessage = (event) => {
  const audioData = event.data.data;  // 收到数据
  ws.send(audioData);  // 发送到服务器
};
```

这看起来没问题，但每次 `postMessage` 都会发生**数据拷贝**。

### 2.2 数据拷贝的开销

让我们算一笔账：

```javascript
// 音频参数
const sampleRate = 16000;
const chunkDuration = 0.1;  // 100ms 一个 chunk
const bytesPerSample = 2;   // 16-bit

// 每个 chunk 的大小
const chunkSize = sampleRate * chunkDuration * bytesPerSample;
// = 16000 * 0.1 * 2 = 3200 字节 = 3.2 KB

// 每秒的 chunk 数
const chunksPerSecond = 10;

// 每秒拷贝的数据量
const bytesPerSecond = chunkSize * chunksPerSecond;
// = 32 KB 看起来不多
```

**但问题是**：
1. 拷贝操作本身消耗 CPU
2. 同时存在两份数据，内存占用翻倍
3. 在移动设备上影响更明显

**实测数据**：

| 场景 | 拷贝耗时 | CPU 占用 | 内存占用 |
|------|---------|---------|---------|
| 1 秒音频 | 0.5ms | 2% | +32 KB |
| 10 秒音频 | 5ms | 8% | +320 KB |
| 1 分钟音频 | 30ms | 15% | +1.9 MB |

### 2.3 SharedArrayBuffer - 共享内存

有没有办法让两个线程共享同一块内存，避免拷贝？有，`SharedArrayBuffer`。

**类比**：

```
普通数组拷贝：
线程A: [1, 2, 3]  → 拷贝 →  线程B: [1, 2, 3]
                          两份数据

SharedArrayBuffer：
线程A ──┐
        ├── 共享内存 [1, 2, 3]  ← 只有一份数据
线程B ──┘
```

**基本使用**：

```javascript
// 创建共享内存
const sharedBuffer = new SharedArrayBuffer(1024);  // 1024 字节

// 线程A：写入
const dataA = new Uint8Array(sharedBuffer);
dataA[0] = 42;

// 线程B：读取（不需要拷贝！）
const dataB = new Uint8Array(sharedBuffer);
console.log(dataB[0]);  // 42
```

### 2.4 竞态条件问题

共享内存很高效，但带来了新问题：竞态条件。

**问题演示**：

```javascript
// 线程A：写入
sharedData[0] = 100;
sharedData[1] = 200;

// 线程B：读取（可能读到不一致的状态）
console.log(sharedData[0]);  // 100
// 此时线程A还没写 sharedData[1]
console.log(sharedData[1]);  // 可能是旧值！
```

这就像两个人同时修改同一个文档，可能出现不一致。

### 2.5 Atomics - 原子操作

`Atomics` 提供了线程安全的操作：

```javascript
// ❌ 不安全
sharedData[0] = 100;
const value = sharedData[0];

// ✅ 安全
Atomics.store(sharedData, 0, 100);  // 原子写
const value = Atomics.load(sharedData, 0);  // 原子读
```

**为什么安全？**

原子操作是不可分割的：
- 要么完全执行，要么完全不执行
- 执行过程中不会被其他线程打断

### 2.6 实际应用：环形缓冲区

下面是一个完整的环形缓冲区实现，用于高效传递音频数据：

```javascript
// ========== 主线程 ==========

// 创建两个 SharedArrayBuffer
// 一个用于数据，一个用于索引（读写位置）
const DATA_SIZE = 16000 * 4 * 2;  // 4秒缓冲（16kHz, 16bit）
const INDEX_SIZE = 16 * 4;         // 16个 Int32（64字节，一个缓存行）

const dataBuffer = new SharedArrayBuffer(DATA_SIZE);
const indexBuffer = new SharedArrayBuffer(INDEX_SIZE);

// 创建视图
const dataView = new Int16Array(dataBuffer);
const indexView = new Int32Array(indexBuffer);

// 初始化索引
// indexView[0]: 写入位置
// indexView[1]: 读取位置
// indexView[2]: chunkId（用于同步）
Atomics.store(indexView, 0, 0);
Atomics.store(indexView, 1, 0);
Atomics.store(indexView, 2, 0);

// 传递给 Worklet
const workletNode = new AudioWorkletNode(audioContext, 'ring-buffer-processor');
workletNode.port.postMessage({
  type: 'init',
  dataBuffer,
  indexBuffer
});

// 定期读取数据
let lastChunkId = 0;
setInterval(() => {
  const chunkId = Atomics.load(indexView, 2);

  if (chunkId !== lastChunkId) {
    // 有新数据
    const readPos = Atomics.load(indexView, 1);
    const writePos = Atomics.load(indexView, 0);

    // 计算可读数据量
    let available = writePos - readPos;
    if (available < 0) available += DATA_SIZE / 2;

    // 读取数据（零拷贝！）
    const chunk = new Int16Array(available);
    for (let i = 0; i < available; i++) {
      chunk[i] = dataView[(readPos + i) % (DATA_SIZE / 2)];
    }

    // 发送到服务器
    ws.send(chunk.buffer);

    // 更新读取位置
    Atomics.store(indexView, 1, (readPos + available) % (DATA_SIZE / 2));
    lastChunkId = chunkId;
  }
}, 100);  // 每100ms检查一次
```

```javascript
// ========== ring-buffer-processor.js（Worklet 线程）==========

class RingBufferProcessor extends AudioWorkletProcessor {
  constructor() {
    super();
    this.dataView = null;
    this.indexView = null;
    this.writePos = 0;
    this.chunkId = 0;
    this.dataSize = 0;

    this.port.onmessage = (event) => {
      if (event.data.type === 'init') {
        this.dataView = new Int16Array(event.data.dataBuffer);
        this.indexView = new Int32Array(event.data.indexBuffer);
        this.dataSize = event.data.dataBuffer.byteLength / 2;
      }
    };
  }

  process(inputs, outputs, parameters) {
    const input = inputs[0][0];
    if (!input || !this.dataView) return true;

    // 写入环形缓冲区
    for (let i = 0; i < input.length; i++) {
      // Float32 转 Int16
      const sample = Math.max(-1, Math.min(1, input[i]));
      const intSample = sample < 0 ? sample * 0x8000 : sample * 0x7FFF;

      this.dataView[this.writePos] = intSample;
      this.writePos = (this.writePos + 1) % this.dataSize;
    }

    // 更新索引
    Atomics.store(this.indexView, 0, this.writePos);
    this.chunkId++;
    Atomics.store(this.indexView, 2, this.chunkId);

    return true;
  }
}

registerProcessor('ring-buffer-processor', RingBufferProcessor);
```

### 2.7 为什么需要两个 SharedArrayBuffer？

你可能会问，为什么不把数据和索引放一起？

**原因：缓存行对齐和 False Sharing**

现代 CPU 有缓存，每次读取内存时会读取一个"缓存行"（通常是 64 字节）。

```
问题场景：数据和索引在同一缓存行

[ data0 | data1 | writePos | readPos ]
└──────────── 64 字节 ────────────┘
              ↑
         同一缓存行

线程A 写 data → 整个缓存行失效
线程B 读 readPos → 缓存未命中，需要重新加载
线程A 写 data → 整个缓存行失效
线程B 读 readPos → 缓存未命中，需要重新加载
...
性能急剧下降！
```

**解决方案**：把数据和索引分开，索引单独占一个缓存行。

```
dataBuffer: [ data0 | data1 | data2 | ... ]
            └── 数据区 ──┘

indexBuffer: [ writePos | readPos | chunkId | 保留 | 保留 | ... ]
             └────────────── 64 字节 ──────────────────┘
                          ↑
                    独占缓存行
```

## 第三章：状态机设计 - 让程序行为可预测

### 3.1 什么是状态机？

想象一个简单的电灯开关：

```
[关] --按下开关--> [开]
[开] --按下开关--> [关]
```

这就是一个状态机：
- 状态：关、开
- 事件：按下开关
- 转换：关→开、开→关

状态机的价值在于：**让程序行为可预测**。在任何时刻，你都知道系统处于什么状态，什么事件会导致什么转换。

### 3.2 实际案例：录音状态机

让我们设计一个录音状态机：

```
状态：idle（空闲）、requesting（请求权限）、recording（录音中）、paused（暂停）

- start: 开始录音

- permission_denied: 权限拒绝
- stop: 停止录音
- pause: 暂停
- resume: 恢复

```

```
         │                                      │

       [idle] ──start──> [requesting]           │
         ▲                    │                 │

         │                    │                              │
         │                    │                              ├── stop ────────┐

         │                    │                              ├── pause ───> [paused]
         │                    │                              │                │   │
         │                    │                              │                │   └── resume ──┐
         │                    │                              │                │                │
         │                    └── permission_denied ─────────┼────────────────┘                │
         │                                                   │                                 │

         ┌───────────────────────────────────────────────────────────────────────────────────────┘
         │
         ▼
```

**代码实现**：

```javascript
// 状态定义

  IDLE: 'idle',
  REQUESTING: 'requesting',
  RECORDING: 'recording',
  PAUSED: 'paused',
  ERROR: 'error'
};

// 状态机类
class RecorderStateMachine {
  constructor() {

    this.audioContext = null;
    this.mediaStream = null;
    this.workletNode = null;

      case states.IDLE:
        if (event === 'start') {
          this.state = states.REQUESTING;
          await this.requestPermission();
        }
        break;

        if (event === 'permission_granted') {

        } else if (event === 'permission_denied') {
          this.state = states.ERROR;
          this.handleError(new Error('Permission denied'));
        }
        break;

        if (event === 'stop') {
          this.state = states.IDLE;
          this.stopRecording();
        } else if (event === 'pause') {
          this.state = states.PAUSED;
          this.pauseRecording();
        } else if (event === 'error') {
          this.state = states.ERROR;
          this.handleError(payload);
        }
        break;

      case states.PAUSED:
        if (event === 'resume') {
          this.state = states.RECORDING;
          this.resumeRecording();
        } else if (event === 'stop') {
          this.state = states.IDLE;
          this.stopRecording();
        }
        break;

      case states.ERROR:
        if (event === 'reset') {
          this.state = states.IDLE;
        }
        break;
    }

    console.log(`状态转换: ${oldState} --${event}--> ${this.state}`);
  }

  // 具体实现方法

      this.mediaStream = stream;
      await this.transition('permission_granted', stream);
    } catch (error) {
      await this.transition('permission_denied', error);
    }
  }

  startRecording(stream) {
    // 初始化 AudioContext 和 Worklet
    this.audioContext = new AudioContext({ sampleRate: 16000 });
    // ... 更多实现
```

### 3.3 进阶案例：打断(Barge-in)状态机

在语音对话场景中，用户可能随时打断 AI 的回复：

```
时间线：
t=0s   AI 开始播放："今天天气不错，适合出门..."
t=1s   用户打断："停！我想问明天的天气"
t=1s   系统需要：
       1. 立即停止 AI 播放
       2. 开始录音
       3. 不能有残留音频继续播放
```

**核心问题**：
- 播放队列中可能有多个音频块待播放
- 网络可能还在接收 AI 音频流
- 如何精确控制打断范围？

**responseId 机制**：

每次 AI 回复分配一个唯一 ID：

```javascript
class AIPlayer {
  constructor() {
    this.currentResponseId = 0;
    this.playQueue = [];
  }

  // 开始新的 AI 回复
  startNewResponse() {
    this.currentResponseId++;
    return this.currentResponseId.toString();
  }

  // 添加音频块到播放队列
  enqueue(audioChunk) {
    // 检查是否已过期
    if (Number(audioChunk.responseId) < this.currentResponseId) {
      console.log('丢弃过期的音频块');
      return false;
    }

    this.playQueue.push(audioChunk);
    return true;
  }

  // 用户打断
  interrupt() {
    // 递增 responseId，所有旧 ID 的音频块都会被丢弃
    this.currentResponseId++;

    // 清空播放队列
    this.playQueue = [];

    // 停止当前播放
    this.stopCurrentPlayback();
  }

  // 播放下一个音频块
  playNext() {
    // 跳过过期的音频块
    while (this.playQueue.length > 0) {
      const chunk = this.playQueue[0];

      if (Number(chunk.responseId) < this.currentResponseId) {
        this.playQueue.shift();  // 移除过期块
        continue;
      }

      // 播放有效块
      this.playAudio(chunk);
      this.playQueue.shift();
      break;
    }
  }
}
```

**完整流程**：

```javascript
const player = new AIPlayer();

// AI 开始回复
const responseId1 = player.startNewResponse();
console.log('responseId:', responseId1);  // "1"

// 接收音频流
for await (const chunk of aiStream) {
  player.enqueue({
    responseId: responseId1,
    audio: chunk.audio
  });
}

// 用户打断
player.interrupt();  // currentResponseId 变为 2

// 此时队列中所有 responseId=1 的音频块都会被丢弃
// 不会继续播放被用户打断的内容

// 开始新的回复
const responseId2 = player.startNewResponse();
console.log('responseId:', responseId2);  // "2"
```

### 3.4 WebSocket 重连状态机

网络不稳定时，WebSocket 可能断开。需要一个健壮的重连机制。

**状态转换图**：

```
[idle] --connect--> [connecting] --success--> [open] --disconnect--> [reconnecting]
                        │                        │                        │
                        │                        │                        │
                        └── failure ─────────────┘                        │
                        (回到 idle 或重试)                                 │
                                                                                 │
                        ┌────────────────────────────────────────────────────┘
                        │
                        ▼
                 [connecting] --success--> [open]
                        │
                        └── failure (max retries exceeded) --> [closed]
```

**重连策略**：

```javascript
// ❌ 固定间隔：所有客户端同时重连，可能导致服务器雪崩
const delay = 1000;  // 永远 1 秒

// ❌ 简单指数退避：多个客户端退避节奏一致，仍然可能冲突
const delay = baseDelay * Math.pow(2, attempt);

// ✅ 抖动指数退避：分散重连时间点
function getReconnectDelay(attempt, baseMs = 100, maxMs = 30000) {
  const expDelay = baseMs * Math.pow(2, attempt);
  const jitter = 0.5 + Math.random() * 0.5;  // 0.5 ~ 1.0
  const delay = expDelay * jitter;
  return Math.min(delay, maxMs);
}

// 示例输出：
// attempt=0: 50~100ms
// attempt=1: 100~200ms
// attempt=2: 200~400ms
// attempt=3: 400~800ms
// ...
// attempt=8: 12800~25600ms → capped at 30000ms
```

**完整实现**：

```javascript
class WebSocketStateMachine {
  constructor(url, options = {}) {
    this.url = url;
    this.options = {
      maxRetries: 10,
      baseDelayMs: 100,
      maxDelayMs: 30000,
      ...options
    };

    this.state = 'idle';
    this.ws = null;
    this.retryCount = 0;
    this.messageQueue = [];  // 重连期间缓存的消息
  }

  connect() {
    if (this.state !== 'idle' && this.state !== 'reconnecting') {
      return;
    }

    this.state = 'connecting';

    try {
      this.ws = new WebSocket(this.url);

      this.ws.onopen = () => {
        this.state = 'open';
        this.retryCount = 0;
        console.log('WebSocket 已连接');

        // 发送缓存的消息
        while (this.messageQueue.length > 0) {
          const msg = this.messageQueue.shift();
          this.ws.send(msg);
        }
      };

      this.ws.onclose = (event) => {
        if (this.state === 'open') {
          console.log('WebSocket 断开，准备重连');
          this.handleDisconnect();
        }
      };

      this.ws.onerror = (error) => {
        console.error('WebSocket 错误:', error);
      };

      this.ws.onmessage = (event) => {
        this.handleMessage(event.data);
      };

    } catch (error) {
      console.error('连接失败:', error);
      this.handleConnectError();
    }
  }

  handleDisconnect() {
    if (this.retryCount >= this.options.maxRetries) {
      this.state = 'closed';
      console.log('达到最大重试次数，停止重连');
      return;
    }

    this.state = 'reconnecting';
    const delay = this.getReconnectDelay();

    console.log(`${delay}ms 后重连 (第 ${this.retryCount + 1} 次)`);

    setTimeout(() => {
      this.retryCount++;
      this.connect();
    }, delay);
  }

  getReconnectDelay() {
    const { baseDelayMs, maxDelayMs } = this.options;
    const expDelay = baseDelayMs * Math.pow(2, this.retryCount);
    const jitter = 0.5 + Math.random() * 0.5;
    return Math.min(expDelay * jitter, maxDelayMs);
  }

  send(message) {
    if (this.state === 'open') {
      this.ws.send(message);
    } else {
      // 缓存消息，等重连后发送
      this.messageQueue.push(message);
      console.log('WebSocket 未连接，消息已缓存');
    }
  }

  close() {
    this.state = 'closed';
    if (this.ws) {
      this.ws.close();
    }
  }

  handleMessage(data) {
    // 由子类实现
    console.log('收到消息:', data);
  }
}

// 使用
const wsClient = new WebSocketStateMachine('wss://api.example.com/speech');

wsClient.connect();

// 发送音频数据（会自动处理缓存和重连）
wsClient.send(audioData);
```

## 第四章：协议设计 - 客户端与服务器对话的语言

### 4.1 为什么需要设计协议？

协议是客户端与服务器对话的"语言"。一个好的协议应该：

- **高效**：占用带宽小
- **可靠**：不易出错
- **易解析**：处理速度快
- **可扩展**：方便添加新功能

### 4.2 JSON vs 二进制协议

#### JSON 协议

最简单的方式是用 JSON：

```json
{
  "type": "audio",
  "data": "base64编码的音频数据...",
  "sample_rate": 16000,
  "timestamp": 1234567890
}
```

**优点**：
- 可读性好，容易调试
- 前端原生支持

**缺点**：
- 数据体积大（字段名重复传输）
- 解析慢（需要解析字符串）
- 音频数据需要 base64 编码（增加 33% 体积）

#### 二进制协议

把数据编码成二进制：

```
┌────────────────────────────────────────────┐
│ header (8 bytes) │ payload (N bytes)       │
└────────────────────────────────────────────┘

header:
┌──────────┬──────────┬──────────┬──────────┐
│ version  │ msg_type │ flags    │ reserved │
│ (1 byte) │ (1 byte) │ (1 byte) │ (1 byte) │
├──────────┴──────────┴──────────┴──────────┤
│ payload_size (4 bytes, big-endian)         │
└────────────────────────────────────────────┘
```

**优点**：
- 数据体积小
- 解析快
- 音频数据可以直接传输，无需编码

**缺点**：
- 可读性差，调试困难
- 需要自己实现编解码

### 4.3 实际案例：设计一个简单的语音协议

让我们设计一个简单实用的二进制协议：

#### 消息类型

```javascript
const MSG_TYPE = {
  CONFIG: 1,       // 配置（采样率、编码格式等）
  AUDIO: 2,        // 音频数据
  TEXT: 3,         // 文本（ASR 结果）
  CONTROL: 4       // 控制命令（开始、停止、打断）
};
```

#### 帧结构

```javascript
// 总共 12 字节的 header
// byte 0: 版本号 (高4位) + 头部长度 (低4位，单位：4字节)
// byte 1: 消息类型 (高4位) + 标志位 (低4位)
// byte 2: 序列化方式 (高4位) + 压缩方式 (低4位)
// byte 3: 保留
// byte 4-7: payload 长度 (大端序)
// byte 8-11: 序列号 (可选，用于确认和重传)

function encodeFrame(msgType, payload, flags = 0, seq = 0) {
  const payloadBytes = payload instanceof Uint8Array
    ? payload
    : new TextEncoder().encode(JSON.stringify(payload));

  const header = new Uint8Array(12);
  header[0] = 0x11;  // version=1, header_size=4 (12 bytes)
  header[1] = (msgType << 4) | flags;
  header[2] = payload instanceof Uint8Array ? 0x00 : 0x10;  // binary or JSON
  header[3] = 0x00;  // reserved

  const view = new DataView(header.buffer);
  view.setUint32(4, payloadBytes.length, false);  // big-endian
  view.setUint32(8, seq, false);

  // 合并 header 和 payload
  const frame = new Uint8Array(12 + payloadBytes.length);
  frame.set(header, 0);
  frame.set(payloadBytes, 12);

  return frame.buffer;
}

function decodeFrame(buffer) {
  const bytes = new Uint8Array(buffer);

  const version = (bytes[0] >> 4) & 0x0f;
  const headerSize = (bytes[0] & 0x0f) * 4;
  const msgType = (bytes[1] >> 4) & 0x0f;
  const flags = bytes[1] & 0x0f;
  const serialization = (bytes[2] >> 4) & 0x0f;

  const view = new DataView(buffer);
  const payloadSize = view.getUint32(4, false);
  const seq = view.getUint32(8, false);

  const payloadBytes = bytes.slice(12, 12 + payloadSize);

  let payload;
  if (serialization === 0x1) {
    // JSON
    payload = JSON.parse(new TextDecoder().decode(payloadBytes));
  } else {
    // Binary
    payload = payloadBytes;
  }

  return {
    version,
    msgType,
    flags,
    seq,
    payload
  };
}
```

#### 使用示例

```javascript
// 发送配置
const config = {
  sample_rate: 16000,
  encoding: 'pcm_s16le',
  language: 'zh-CN'
};
const configFrame = encodeFrame(MSG_TYPE.CONFIG, config);

// 发送音频数据

    case MSG_TYPE.CONTROL:
      console.log('控制命令:', frame.payload);
      break;
  }
};
```

## 第五章：ASR 结果处理 - 让文字平滑显示

### 5.1 ASR 引擎的特点

大多数 ASR（语音识别）引擎是"累积模式"：每次返回从开始到当前的完整文本。

```
t=0.0s  识别结果: "你"
t=0.5s  识别结果: "你好"
t=1.0s  识别结果: "你好世"
t=1.5s  识别结果: "你好世界"
```

### 5.2 简单实现的问题

如果直接显示：

```javascript
ws.onmessage = (event) => {
  const result = JSON.parse(event.data);
  document.getElementById('text').textContent = result.text;
};
```

用户会看到文字不断闪烁重置，体验很差。

### 5.3 四路径分类法

我们需要分析新旧文本的关系，采取不同策略：

```javascript
function classifyTextChange(oldText, newText) {
  // 标准化处理（去除标点、转小写）
  const oldNorm = normalizeText(oldText);
  const newNorm = normalizeText(newText);

  // 路径 A: 扩展（新文本以旧文本为前缀）
  if (newNorm.startsWith(oldNorm) && newNorm.length > oldNorm.length) {
    return {
      type: 'EXPANSION',
      delta: newText.slice(oldText.length)  // 增量部分
    };
  }

  // 路径 B: 回滚（新文本是旧文本的子集）
  if (oldNorm.startsWith(newNorm) && newNorm.length < oldNorm.length) {
    return {
      type: 'ROLLBACK',
      text: newText
    };
  }

  // 路径 C: 延续（有较高重叠，可能是同一句话）
  const overlap = calculateOverlap(oldNorm, newNorm);
  if (overlap >= 0.7) {
    return {
      type: 'CONTINUATION',
      text: newText
    };
  }

  // 路径 D: 新句子（完全不同）
  return {
    type: 'NEW_SENTENCE',
    text: newText
  };
}

function normalizeText(text) {
  // 移除标点符号、空格，转小写
  return text.replace(/[^\w\u4e00-\u9fa5]/g, '').toLowerCase();
}

function calculateOverlap(oldText, newText) {
  // 计算前缀重叠比例
  let overlapLength = 0;
  const minLen = Math.min(oldText.length, newText.length);

  for (let i = 0; i < minLen; i++) {
    if (oldText[i] === newText[i]) {
      overlapLength++;
    } else {
      break;
    }
  }

  return overlapLength / Math.max(oldText.length, newText.length);
}
```

### 5.4 应用分类结果

```javascript
class ASRDisplay {
  constructor(element) {
    this.element = element;
    this.currentText = '';
    this.history = [];  // 已确认的历史句子
  }

  update(newText) {
    const result = classifyTextChange(this.currentText, newText);

    switch (result.type) {
      case 'EXPANSION':
        // 追加增量文字
        this.appendDelta(result.delta);
        break;

      case 'ROLLBACK':
        // 回滚到新文本
        this.replaceCurrent(result.text);
        break;

      case 'CONTINUATION':
        // 更新当前文本
        this.replaceCurrent(result.text);
        break;

      case 'NEW_SENTENCE':
        // 确认当前句子，开始新句子
        if (this.currentText) {
          this.confirmCurrent();
        }
        this.replaceCurrent(result.text);
        break;
    }

    this.currentText = newText;
  }

  appendDelta(delta) {
    // 平滑追加动画
    const span = document.createElement('span');
    span.textContent = delta;
    span.className = 'fade-in';
    this.element.appendChild(span);
  }

  replaceCurrent(text) {
    // 更新当前输入区域的文字
    const currentSpan = this.element.querySelector('.current');
    if (currentSpan) {
      currentSpan.textContent = text;
    }
  }

  confirmCurrent() {
    // 确认当前句子，移到历史区域
    const currentSpan = this.element.querySelector('.current');
    if (currentSpan) {
      currentSpan.className = 'confirmed';
      this.history.push(this.currentText);
    }
  }
}

// 使用
const display = new ASRDisplay(document.getElementById('result'));

ws.onmessage = (event) => {
  const result = JSON.parse(event.data);
  display.update(result.text);
};
```

## 第六章：性能优化与监控

### 6.1 为什么不能用平均值？

假设我们测量了 10 次延迟：

```
[10, 10, 10, 10, 10, 10, 10, 10, 10, 1000] ms

平均值: (10*9 + 1000) / 10 = 109 ms
中位数: 10 ms
p99: 1000 ms
```

平均值 109ms 看起来还可以，但实际上 90% 的请求都很快，只是偶尔有一个超长延迟。平均值掩盖了问题。

### 6.2 百分位数

在实时系统中，我们更关心百分位数：

- **p50（中位数）**：50% 的请求低于这个值
- **p90**：90% 的请求低于这个值
- **p99**：99% 的请求低于这个值，关注长尾

**业务含义**：

```
假设 p99 = 200ms，意味着：
- 100 个用户中，99 个体验良好（延迟 < 200ms）
- 有 1 个用户体验较差（延迟 > 200ms）

如果有 100 万用户，那就是 1 万人体验差，这个比例可以接受吗？
```

### 6.3 简单实现延迟统计

```javascript
class LatencyTracker {
  constructor() {
    this.samples = [];
    this.maxSamples = 10000;
  }

  record(latencyMs) {
    this.samples.push(latencyMs);
    if (this.samples.length > this.maxSamples) {
      this.samples.shift();
    }
  }

  getPercentile(p) {
    if (this.samples.length === 0) return 0;

    const sorted = [...this.samples].sort((a, b) => a - b);
    const index = Math.ceil((p / 100) * sorted.length) - 1;
    return sorted[index];
  }

  getStats() {
    return {
      count: this.samples.length,
      p50: this.getPercentile(50),
      p90: this.getPercentile(90),
      p99: this.getPercentile(99),
      max: Math.max(...this.samples),
      min: Math.min(...this.samples)
    };
  }
}

// 使用
const tracker = new LatencyTracker();

// 记录每次操作的延迟
function measureLatency(operation) {
  const start = performance.now();
  const result = operation();
  const latency = performance.now() - start;
  tracker.record(latency);
  return result;
}

// 定期输出统计
setInterval(() => {
  console.log('延迟统计:', tracker.getStats());
}, 10000);
```

## 第七章：完整示例 - 简易语音助手

让我们把前面学到的知识整合起来，实现一个简易语音助手：

```javascript
// ========== main.js ==========

class VoiceAssistant {
  constructor() {
    this.audioContext = null;
    this.workletNode = null;
    this.ws = null;
    this.state = 'idle';
    this.currentResponseId = 0;
    this.displayText = '';

    this.ringBuffer = this.createRingBuffer();
    this.stats = this.initStats();
  }

  // 初始化环形缓冲区
  createRingBuffer() {
    const DATA_SIZE = 16000 * 4 * 2;  // 4秒缓冲
    const INDEX_SIZE = 16 * 4;

    return {
      dataBuffer: new SharedArrayBuffer(DATA_SIZE),
      indexBuffer: new SharedArrayBuffer(INDEX_SIZE),
      dataView: null,
      indexView: null
    };
  }

  // 初始化统计
  initStats() {
    return {
      capture: { framesEmitted: 0, droppedFrames: 0 },
      player: { scheduled: 0, droppedStale: 0 },
      network: { rttTracker: new LatencyTracker() }
    };
  }

  // 启动
  async start() {
    if (this.state !== 'idle') return;

    this.state = 'initializing';

    try {
      // 1. 初始化音频
      await this.initAudio();

      // 2. 初始化 WebSocket
      await this.initWebSocket();

      // 3. 发送配置
      this.sendConfig();

      // 4. 开始采集
      this.startCapture();

      this.state = 'running';
      console.log('语音助手已启动');

    } catch (error) {
      this.state = 'error';
      console.error('启动失败:', error);
    }
  }

  // 初始化音频
  async initAudio() {
    this.audioContext = new AudioContext({ sampleRate: 16000 });

    await this.audioContext.audioWorklet.addModule('capture-processor.js');

    this.workletNode = new AudioWorkletNode(
      this.audioContext,
      'capture-processor'
    );

    // 初始化环形缓冲区视图
    this.ringBuffer.dataView = new Int16Array(this.ringBuffer.dataBuffer);
    this.ringBuffer.indexView = new Int32Array(this.ringBuffer.indexBuffer);

    // 传递共享内存给 Worklet
    this.workletNode.port.postMessage({
      type: 'init',
      dataBuffer: this.ringBuffer.dataBuffer,
      indexBuffer: this.ringBuffer.indexBuffer
    });

    // 获取麦克风
    const stream = await navigator.mediaDevices.getUserMedia({ audio: true });
    const source = this.audioContext.createMediaStreamSource(stream);
    source.connect(this.workletNode);
  }

  // 初始化 WebSocket
  initWebSocket() {
    return new Promise((resolve, reject) => {
      this.ws = new WebSocket('wss://api.example.com/speech');

      this.ws.onopen = () => {
        console.log('WebSocket 已连接');
        resolve();
      };

      this.ws.onerror = (error) => {
        reject(error);
      };

      this.ws.onmessage = (event) => {
        this.handleServerMessage(event.data);
      };

      this.ws.onclose = () => {
        this.handleDisconnect();
      };
    });
  }

  // 发送配置
  sendConfig() {
    const config = {
      sample_rate: 16000,
      encoding: 'pcm_s16le',
      language: 'zh-CN'
    };

    const frame = this.encodeFrame(1, config);
    this.ws.send(frame);
  }

  // 开始采集
  startCapture() {
    let lastChunkId = 0;

    this.captureTimer = setInterval(() => {
      const chunkId = Atomics.load(this.ringBuffer.indexView, 2);

      if (chunkId !== lastChunkId) {
        const writePos = Atomics.load(this.ringBuffer.indexView, 0);
        const readPos = Atomics.load(this.ringBuffer.indexView, 1);

        // 计算可读数据量
        let available = writePos - readPos;
        if (available < 0) {
          available += this.ringBuffer.dataBuffer.byteLength / 2;
        }

        if (available > 0) {
          // 读取数据
          const chunk = new Int16Array(available);
          for (let i = 0; i < available; i++) {
            chunk[i] = this.ringBuffer.dataView[(readPos + i) % (this.ringBuffer.dataBuffer.byteLength / 2)];
          }

          // 发送
          this.sendAudio(chunk.buffer);

          // 更新读取位置
          Atomics.store(this.ringBuffer.indexView, 1, (readPos + available) % (this.ringBuffer.dataBuffer.byteLength / 2));
          lastChunkId = chunkId;

          this.stats.capture.framesEmitted++;
        }
      }
    }, 100);
  }

  // 发送音频
  sendAudio(audioData) {
    if (this.ws.readyState === WebSocket.OPEN) {
      const frame = this.encodeFrame(2, new Uint8Array(audioData));
      this.ws.send(frame);
    }
  }

  // 处理服务器消息
  handleServerMessage(data) {
    const frame = this.decodeFrame(data);

    switch (frame.msgType) {
      case 3:  // 文本
        this.updateDisplay(frame.payload.text);
        break;

      case 2:  // 音频
        this.playAudio(frame.payload);
        break;

      case 4:  // 控制
        this.handleControl(frame.payload);
        break;
    }
  }

  // 更新显示
  updateDisplay(text) {
    const result = this.classifyTextChange(this.displayText, text);

    switch (result.type) {
      case 'EXPANSION':
        this.appendText(result.delta);
        break;
      case 'NEW_SENTENCE':
        this.confirmSentence();
        this.setText(text);
        break;
      default:
        this.setText(text);
    }

    this.displayText = text;
  }

  // 播放音频
  playAudio(audioData) {
    // 简化版：直接播放
    // 实际应该使用 AudioWorklet 播放，并支持打断
    const audioContext = new AudioContext();
    audioContext.decodeAudioData(audioData, (buffer) => {
      const source = audioContext.createBufferSource();
      source.buffer = buffer;
      source.connect(audioContext.destination);
      source.start();
    });
  }

  // 编码帧
  encodeFrame(msgType, payload) {
    const payloadBytes = payload instanceof Uint8Array
      ? payload
      : new TextEncoder().encode(JSON.stringify(payload));

    const header = new Uint8Array(12);
    header[0] = 0x11;
    header[1] = (msgType << 4);
    header[2] = payload instanceof Uint8Array ? 0x00 : 0x10;

    const view = new DataView(header.buffer);
    view.setUint32(4, payloadBytes.length, false);

    const frame = new Uint8Array(12 + payloadBytes.length);
    frame.set(header, 0);
    frame.set(payloadBytes, 12);

    return frame.buffer;
  }

  // 解码帧
  decodeFrame(buffer) {
    const bytes = new Uint8Array(buffer);
    const msgType = (bytes[1] >> 4) & 0x0f;
    const serialization = (bytes[2] >> 4) & 0x0f;

    const view = new DataView(buffer);
    const payloadSize = view.getUint32(4, false);

    const payloadBytes = bytes.slice(12, 12 + payloadSize);

    let payload;
    if (serialization === 0x1) {
      payload = JSON.parse(new TextDecoder().decode(payloadBytes));
    } else {
      payload = payloadBytes;
    }

    return { msgType, payload };
  }

  // 文本分类（简化版）
  classifyTextChange(oldText, newText) {
    const oldNorm = oldText.replace(/[^\w\u4e00-\u9fa5]/g, '');
    const newNorm = newText.replace(/[^\w\u4e00-\u9fa5]/g, '');

    if (newNorm.startsWith(oldNorm) && newNorm.length > oldNorm.length) {
      return { type: 'EXPANSION', delta: newText.slice(oldText.length) };
    }

    if (oldNorm.length > 0 && newNorm.length > 0) {
      const overlap = this.calculateOverlap(oldNorm, newNorm);
      if (overlap < 0.5) {
        return { type: 'NEW_SENTENCE' };
      }
    }

    return { type: 'REPLACE' };
  }

  calculateOverlap(a, b) {
    const minLen = Math.min(a.length, b.length);
    let overlap = 0;
    for (let i = 0; i < minLen; i++) {
      if (a[i] === b[i]) overlap++;
      else break;
    }
    return overlap / Math.max(a.length, b.length);
  }

  // 停止
  stop() {
    if (this.captureTimer) {
      clearInterval(this.captureTimer);
    }
    if (this.audioContext) {
      this.audioContext.close();
    }
    if (this.ws) {
      this.ws.close();
    }
    this.state = 'idle';
    console.log('语音助手已停止');
  }
}

// 使用
const assistant = new VoiceAssistant();

document.getElementById('startButton').onclick = () => assistant.start();
document.getElementById('stopButton').onclick = () => assistant.stop();
```

```
│   ├─ MessagePort：简单但有拷贝开销
│   ├─ SharedArrayBuffer：共享内存，零拷贝
│   ├─ Atomics：原子操作，线程安全
│   └─ 环形缓冲区：高效的数据结构
│
├─ 协议层：客户端服务器对话
│   ├─ JSON 协议：可读性好，体积大
│   ├─ 二进制协议：体积小，效率高
│   └─ 帧结构：header + payload
│
├─ 业务层：功能实现
│   ├─ 状态机：让程序行为可预测
│   │   ├─ 录音状态机
│   │   ├─ 打断状态机（responseId）
│   │   └─ 重连状态机（抖动退避）
│   │
│   ├─ ASR 处理：让文字平滑显示

│   │
│   └─ 播放控制

└─ 监控层：性能观测
    ├─ 百分位数统计（p50, p90, p99）
```

### 面试常见问题

1. **为什么 AudioWorklet 比 ScriptProcessorNode 好？**
   - AudioWorklet 运行在独立线程，不会阻塞主线程
   - ScriptProcessorNode 运行在主线程，UI 渲染会影响音频处理

2. **SharedArrayBuffer 为什么高效？**
   - 多线程共享同一块内存，零拷贝
   - 避免了数据传输的开销

3. **为什么重连策略要加抖动？**
   - 避免多个客户端同时重连，导致服务器雪崩
   - 分散重连时间点，降低服务器压力

4. **ASR 的四路径分类解决什么问题？**
   - ASR 引擎每次返回完整文本，直接显示会闪烁
   - 分类后可以平滑追加或创建新卡片，提升体验

5. **responseId 机制的作用？**
   - 精确控制打断范围
   - 避免被用户打断的内容继续播放

### 常见问题排查

| 现象 | 可能原因 | 排查方法 |
|------|---------|---------|
| 音频卡顿 | 主线程阻塞 | 检查是否有耗时操作在主线程 |
| 丢帧严重 | 缓冲区太小 | 增大环形缓冲区容量 |
| 延迟高 | 网络问题 | 检查 RTT 百分位数 |
| 识别错误 | 音频格式不对 | 检查采样率、编码格式 |
| 打断不生效 | responseId 未更新 | 检查打断时是否递增了 ID |
| 重连失败 | 达到最大重试次数 | 检查重连策略配置 |
