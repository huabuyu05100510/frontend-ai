# 定位思考：能不能做视频会议、直播？

> 核心问题：既然有音频能力，为什么不做视频会议？
> 回答原则：诚实展现能力边界，清晰说明定位选择

---

## 一、技术能力分析：能不能做？

### 1.1 技术上能做到什么？

| 能力 | voice-kit已有 | 视频会议需要 | 差距 |
|------|--------------|-------------|------|
| **音频采集** | ✅ AudioWorklet完整实现 | 需要 | 无差距 |
| **音频播放** | ✅ 时间调度队列完整实现 | 需要 | 无差距 |
| **音频编解码** | ✅ Opus WASM已有 | 需要Opus | 无差距 |
| **降噪/AEC** | ✅ 已集成 | 需要 | 无差距 |
| **WebSocket传输** | ✅ 重连+背压完整 | 需要 | 无差距 |
| **视频采集** | ❌ 无 | MediaStream | **需要实现** |
| **视频编解码** | ❌ 无 | VP8/H264/WASM | **需要实现** |
| **多人同步** | ❌ 无 | SFU/MCU架构 | **需要实现** |
| **布局渲染** | ❌ 无 | Canvas/WebGL布局 | **需要实现** |
| **信令协议** | ❌ 无 | SDP/ICE协商 | **需要实现** |

### 1.2 如果要做，需要补充什么？

**视频层（新增）**：
```typescript
interface IVideoCapture {
  start(opts?: { deviceId?: string; resolution?: '720p' | '1080p' }): Promise<void>;
  stop(): Promise<void>;
  frames(): AsyncIterable<VideoFrame>;  // 视频帧流
}

interface IVideoPlayer {
  enqueue(frame: VideoFrame): void;
  layout(mode: 'grid' | 'speaker'): void;  // 多人布局
}

interface VideoFrame {
  data: ArrayBuffer;  // YUV或RGB
  width: number;
  height: number;
  timestamp: number;
}
```

**编解码层（新增）**：
```typescript
interface IVideoCodec {
  encode(frame: VideoFrame): Promise<ArrayBuffer>;
  decode(data: ArrayBuffer): Promise<VideoFrame>;
}
// 实现：VP8 WASM / H264 WASM / libvpx
```

**多人同步（新增）**：
```typescript
interface IMultiPartySync {
  join(roomId: string): Promise<void>;
  leave(): Promise<void>;
  onUserJoin(cb: (userId: string) => void): () => void;
  onUserLeave(cb: (userId: string) => void): () => void;
  getParticipants(): Participant[];

// 需要：SFU服务端（mediasoup/Janus）或 MCU
```

**工作量估算**：
- 视频采集+播放：2周
- 视频编解码（WASM集成）：1周
- 多人同步协议：2周
- 布局渲染：1周
- 信令协商：1周
- **总计：约7周**

## 二、定位选择：为什么不做？

### 2.1 市场分析

**视频会议市场格局**：

| 公司 | 产品 | 市场份额 | 技术特点 |
|------|------|---------|---------|
| Zoom | Zoom会议 | ~40% | 自研编解码、全球CDN |
| 腾讯 | 腾讯会议 | ~25%（国内） | 小程序生态、社交优势 |
| 阿里 | 钉钉会议 | ~20%（国内） | 企业协同、钉钉生态 |
| Google | Google Meet | ~10% | Gmail生态、免费策略 |
| Microsoft | Teams | ~5% | Office生态 |

**市场特点**：
- 巨头垄断，份额集中
- 生态依赖（邮箱、企业工具）
- 需要全球CDN基础设施
- 需要SFU/MCU服务端集群

**voice-kit如果做视频会议**：
- 没有生态优势（不依附于邮箱/企业工具）
- 没有基础设施（没有全球CDN）
- 需要自建SFU服务端（成本高）
- **市场竞争力弱**

### 2.2 技术投入产出分析

**视频会议的技术投入**：

| 投入项 | 工作量 | 技术深度 | 市场价值 |
|--------|--------|---------|---------|
| 视频采集/播放 | 2周 | 中等（MediaStream） | 一般 |
| 视频编解码 | 1周 | 低（调库） | 低（已有成熟库） |
| 多人同步 | 2周 | 高（分布式系统） | 高 |
| 布局渲染 | 1周 | 低（Canvas） | 低 |
| 信令协商 | 1周 | 中等（SDP/ICE） | 中等 |
| **总计** | **7周** | **大部分是调库** | **市场竞争力弱** |

**语音场景的技术投入**：

| 投入项 | 工作量 | 技术深度 | 市场价值 |
|--------|--------|---------|---------|
| Barge-in竞态 | 1周 | 极高（TLA+证明） | 极高（差异化） |
| 流式去重 | 1周 | 高（算法设计） | 高 |
| 延迟观测 | 1周 | 极高（统计学理论） | 极高（SLA价值） |
| 协议逆向 | 1周 | 高（协议分析） | 高 |
| 跨端抽象 | 1周 | 高（架构设计） | 中等 |
| **总计** | **5周** | **全部是深度技术** | **差异化明显** |

**对比结论**：
- 视频会议：7周投入，大部分调库，市场竞争力弱
- 语音场景：5周投入，全部深度技术，差异化明显
- **投入产出比：语音场景更优**

### 2.3 差异化价值分析

**视频会议的差异化点**：

| 差异化 | 现有方案 | voice-kit可能的做法 | 竞争力 |
|--------|---------|-------------------|--------|
| 编解码效率 | Zoom自研VP8优化 | 调用libvpx WASM | 低（不如Zoom） |
| 多人同步 | SFU集群 | 自建SFU（成本高） | 低（成本劣势） |
| 布局优化 | Canvas/WebGL | Canvas布局 | 低（技术门槛低） |

**语音场景的差异化点**：

| 差异化 | 现有方案 | voice-kit做法 | 竞争力 |
|--------|---------|--------------|--------|
| Barge-in竞态 | stopPlayback（有bug） | TLA+证明 | **极高**（会TLA+的<1%） |
| 流式去重 | 滑动窗口（有问题） | 四路径Reducer | **高**（懂算法的少） |
| 延迟观测 | 滑动窗口（误差大） | HDR Histogram | **极高**（懂统计学的少） |
| 协议适配 | 各家自研 | 抽象接口 | **高** |

**对比结论**：
- 视频会议：差异化低，技术门槛低，别人也能做
- 语音场景：差异化高，技术门槛高，别人不会做
- **战略选择：聚焦高差异化领域**

## 三、如果要做，voice-kit的价值是什么？

### 3.1 voice-kit作为音频组件

**场景1：视频会议产品用voice-kit做音频层**

```
视频会议产品架构：
┌─────────────────────────────────────┐
│  应用层：Zoom/腾讯会议/钉钉会议         │
└─────────────────────────────────────┘
              ↓
┌─────────────────────────────────────┐
│  场景层：多人同步、布局渲染             │  ← 产品自研
└─────────────────────────────────────┘
              ↓
┌─────────────────────────────────────┐
│  音频层：采集/播放/降噪/编解码          │  ← 用voice-kit
└─────────────────────────────────────┘
              ↓
┌─────────────────────────────────────┐
│  传输层：WebSocket/WebRTC             │  ← 产品自研或用LiveKit
└─────────────────────────────────────┘
```

**voice-kit提供的音频能力**：
- AudioWorklet采集（稳定20ms帧）
- 时间调度播放（无咔哒声）
- Opus编解码（自适应码率）
- 降噪/AEC（WebAudio处理）
- Barge-in竞态处理（打断立即生效）
- 延迟观测（HDR Histogram）

**价值**：
- 视频会议产品不需要自己写音频层脏活
- 直接用voice-kit，音频质量有保证
- **定位：音频层组件**

### 3.2 voice-kit + LiveKit组合

**组合架构**：
```
┌─────────────────────────────────────┐
│  应用层：自研视频会议产品               │
└─────────────────────────────────────┘
              ↓
┌─────────────────────────────────────┐
│  视频层：LiveKit提供                  │  ← LiveKit
│  - 视频采集/播放                       │
│  - WebRTC传输                         │
│  - 多人同步（SFU）                     │
└─────────────────────────────────────┘
              ↓
┌─────────────────────────────────────┐
│  音频层：voice-kit提供                │  ← voice-kit
│  - AudioWorklet采集                   │
│  - Barge-in竞态处理                   │
│  - 延迟观测                            │
│  - 流式去重                            │
└─────────────────────────────────────┘
```

**组合优势**：
- LiveKit：解决视频传输、多人同步（它擅长）
- voice-kit：解决音频竞态、观测、去重（我们擅长）
- **互补而非竞争**

## 四、面试应对：诚实展现定位思考

### 4.1 面试官问："能不能做视频会议？"

**诚实回答**：

> "技术上可以。音频能力voice-kit已经有了——AudioWorklet采集、时间调度播放、Opus编解码、降噪/AEC。如果要加视频，需要补充视频采集、视频编解码、多人同步协议、布局渲染，大约7周工作量。
> 
> 但我选择不做视频会议，有三个原因：
> 
> 第一，市场格局：视频会议被Zoom、腾讯、钉钉垄断，有生态优势，我们没有。
> 
> 第二，投入产出：视频会议7周投入，大部分是调库（调用libvpx、Canvas），技术门槛低，别人也能做；语音场景5周投入，全部是深度技术（TLA+证明、统计学理论），别人不会做。投入产出比语音场景更优。
> 
> 第三，差异化：视频会议的差异化低，Zoom自研编解码、自建SFU集群，我们调库竞争不过；语音场景的差异化高，Barge-in竞态、HDR Histogram延迟观测，会TLA+、懂统计学的前端<1%，这是真正的壁垒。
> 
> 所以我聚焦语音场景，做别人不会做的脏活，而不是做别人已经做得很好的视频会议。"

### 4.2 面试官追问："如果公司要做视频会议，你怎么定位？"

**定位回答**：

> "如果公司要做视频会议，我会定位voice-kit为音频层组件，而不是全栈视频会议SDK。
> 
> 视频层用LiveKit或自研——它们解决视频采集、WebRTC传输、多人同步，这是它们擅长的；
> 
> 音频层用voice-kit——我们解决AudioWorklet采集、Barge-in竞态、延迟观测、流式去重，这是我们擅长的。
> 
> 这是互补而非竞争。voice-kit专注于语音交互的脏活，让视频会议产品不需要自己写音频层，直接用我们就有质量保证。"

### 4.3 面试官追问："你的野心不够大？"

**战略回答**：

> "这不是野心小，而是战略清晰。
> 
> Zoom做了15年视频会议，自研编解码、自建全球CDN、积累SFU架构，这是基础设施优势，我们短期无法超越。
> 
> 但语音场景的脏活——Barge-in竞态、流式去重、延迟观测——这些是'每个语音应用都要重写一遍'的问题，Zoom、腾讯会议、钉钉会议都在重复写，没有沉淀成基建。
> 
> 我聚焦这个空白，做别人不做的事，而不是做别人已经做得很好的事。这是差异化战略，不是野心小。"

## 五、定位总结

### 能做但选择不做的原因

| 原因 | 说明 |
|------|------|
| **市场格局** | 视频会议被巨头垄断，有生态优势 |
| **投入产出** | 视频会议大部分调库，语音场景全部深度技术 |
| **差异化** | 视频会议门槛低，语音场景壁垒高 |
| **战略选择** | 做别人不做的事，而不是做别人已经做得好的事 |

### 如果要做，voice-kit的定位

**定位**：音频层组件，而非全栈视频会议SDK

**组合方案**：
- 视频层：LiveKit（或自研）
- 音频层：voice-kit（音频脏活）
- **互补而非竞争**

### 面试核心

**诚实**：技术上可以，但战略上选择不做

**清晰**：三个原因（市场、投入产出、差异化）

**定位**：音频层组件，与LiveKit互补

---

**总结：展现战略思考，不是技术能力不足，而是战略选择聚焦。**
