## 一、项目定位

### 1.1 不是什么

**不是**又一个音频包装器——LiveKit、Agora已做得很好。

**不是**通用WebRTC SDK——它们解决连接建立，我们解决**业务场景**。

### 1.2 是什么

**是**把9个语音场景中"难的那一层"沉淀成：
- **可移植核心**：零平台依赖的纯TS包
- **可替换适配器**：Web/小程序/Electron实现
- **场景级状态机**：转写/对话/传译/克隆/播客

**核心价值**：通用SDK不解决、但每个语音应用都要重写一遍的"脏活累活"：
- Barge-in竞态消除
- 流式ASR乱序去重
- 端到端延迟观测
- 跨端抽象

```
┌─────────────────────────────────────────────────────────┐
│                    L5 UI Layer                           │

│              react / vue / taro (小程序)                 │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│                   L3 Scene Layer                         │
│   scene-transcribe / scene-converse / scene-interpret   │
│   scene-tts / scene-clone / scene-podcast               │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│                L2 Adapter Layer                          │
│  adapter-web (AudioWorklet) / adapter-taro (小程序)      │
│  adapter-electron / adapter-node / adapter-mock         │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│                 L1 Core Layer                            │
│  core-types / core-utils / core-transport-ws            │
│  core-reducer-* / core-protocol-* / core-observability  │
└─────────────────────────────────────────────────────────┘
```

### 2.1 依赖规则（eslint-plugin-boundaries强制）

- **core-\***：只能依赖 core-\*，禁止DOM/RN/小程序API
- **adapter-\***：实现core-types接口，可依赖任意core-\*
- **scene-\***：通过依赖注入消费adapter，**永不直接import**
- **react/vue**：薄绑定，只暴露公共API
- **ui-\***：只依赖 react/vue + core-types

### 2.2 包体积预算

| 包 | gzip上限 | 说明 |
|---|---------|------|
| reducer-transcription | 6 KB | 核心去重逻辑 |
| protocol-volc-asr | 4 KB | 二进制编解码 |
| adapter-web | 12 KB | 不含懒加载WASM |
| react hooks | 8 KB | 框架绑定 |
| scene-converse | 45 KB | 全量对话场景 |

## 三、核心接口契约

### 3.1 音频采集

```typescript
interface AudioFormat {
  sampleRate: 8000|16000|24000|44100|48000;
  channels: 1|2;
  encoding: 'pcm-s16le'|'pcm-f32le'|'opus'|'mp3';
}

interface AudioChunk {
  data: ArrayBuffer;          // Int16 PCM
  chunkId: number;            // 单调递增，用于RTT回显
  captureTsMono: number;      // performance.now()
  durationMs: number;
  isSpeech?: boolean;         // VAD填充
}

interface IAudioCapture {
  readonly format: AudioFormat;
  start(opts?: CaptureStartOptions): Promise<void>;
  stop(): Promise<void>;
  chunks(): AsyncIterable<AudioChunk>;  // 拉模式，天然背压
  getStats(): CaptureStats;
}
```

### 3.2 音频播放

```typescript
interface PlaybackChunk {
  data: ArrayBuffer;
  responseId: string;         // Barge-in门控键
  seq: number;                // 同responseId内单调
  format: AudioFormat;
  isFinal?: boolean;
}

interface IAudioPlayer {
  enqueue(c: PlaybackChunk): void;
  interrupt(responseId?: string): void;
  flush(responseId: string): Promise<void>;
  getScheduledEndTime(responseId: string): number|null;
  onEnded(cb: (responseId: string) => void): () => void;
  getStats(): PlayerStats;
}
```

### 3.3 传输层

```typescript
interface ITransport {
  connect(url: string, opts?: TransportOptions): Promise<void>;
  send(msg: {kind:'text'|'binary'; data: string|ArrayBuffer}): void;
  messages(): AsyncIterable<TransportMessage>;
  state(): 'idle'|'connecting'|'open'|'reconnecting'|'closed';
  onStateChange(cb: (s: TransportState) => void): () => void;
  bufferedAmount(): number;
  close(code?: number, reason?: string): void;
}

interface TransportOptions {
  reconnect?: {
    strategy: 'jittered-exponential';
    baseMs: number;
    maxMs: number;
    maxAttempts?: number;
  };
  backpressure?: {
    highWaterBytes: number;
    lowWaterBytes: number;
    onPressure: (paused: boolean) => void;
  };
}
```

## 四、场景层设计

### 4.1 scene-transcribe · 实时转写

**编排**：
```
IAudioCapture → IResampler(→16k) → IVAD(可选) 
  → protocol-volc-asr → ITransport 
  → reducer-transcription → state
```

**状态机**：
```
idle → requesting-perm → capturing → streaming 
  ⇄ reconnecting → stopping → finalized
```

**API**：
```typescript
const t = createTranscribeScene(deps, {
  engine: 'volc',
  lang: 'zh-CN',
  punctuation: true,
  diarization: true
});

t.start();
for await (const s of t.state()) {
  render(s.cards);
}
t.finalize();
```

### 4.2 scene-converse · 实时对话（王冠场景）

**编排**：scene-transcribe (输入) + scene-tts (输出) + reducer-conversation

**关键技术**：responseId门控的Barge-in状态机

**interrupt()四步原子操作**：
1. 自增 `currentResponseId`
2. 丢弃队列中所有 `chunk.responseId < current` 的块
3. `AudioBufferSourceNode.stop(currentTime)`
4. 等 `onended` 触发且无在途解码后才emit `barge-in-complete`

**修复现有bug**：`useRealtimeConversation.ts` 的竞态泄漏

### 4.3 scene-tts · 时间调度播放

**编排**：protocol-volc-tts → IAudioPlayer时间调度队列

**核心技术**：
```typescript
source.start(nextStartTime);
nextStartTime = max(ctx.currentTime + ε, lastScheduledEnd);
```

**暴露 `getScheduledEndTime`**：让上层决定何时解麦

## 五、横切关注点

### 5.1 可观测性

**chunk_id → RTT回显协议**：
1. Worklet帧边界打 `chunkId + captureTsMono`
2. 服务端ack回传 `chunkId`
3. 客户端 `rttMs = mono() - captureMap.get(chunkId)`
4. 入HDR Histogram（对数线性桶，3位有效数字）

**指标导出**：
- `voice.capture.underrun_count`
- `voice.playback.gap_ms` (HDR)
- `voice.transport.rtt_ms` (HDR)
- `voice.reducer.apply_ms`

### 5.2 重连与会话恢复

**抖动指数退避**：
```typescript
delay = base * 2^attempt * (0.5 + rand()*0.5)
```

**恢复协议**：
```json
{"type":"resume","token":T,"lastServerSeq":N}
```

服务端从 N+1 回放；失败则fresh会话。

### 5.3 背压

**监控 `bufferedAmount`**：
- 超 `highWaterBytes` → `onPressure(true)`
- 降 `lowWaterBytes` → `onPressure(false)`

**场景策略**：
- 转写：切环形丢弃模式
- 对话：静麦 + UI警告

### 5.4 测试策略

**单元测试**：vitest，覆盖率目标≥90%

**属性测试（fast-check）**：
- 幂等性：同partial应用两次状态相同
- 去重收敛：任意partial/final交错最终文本一致
- 说话人颜色：djb2跨运行稳定

**黄金fixture测试**：
- 真实会话抓帧 → 解码 → 快照

**E2E测试**：
- Playwright + mock server

## 六、平台适配器

### 6.1 adapter-web（一期主力）

**采集**：
- AudioWorklet + SharedArrayBuffer零拷贝
- 无SAB时降级MessagePort.postMessage

**播放**：
- AudioContext时间调度队列
- 漂移补偿

**限制**：
- 需 `crossOriginIsolated` 启用SAB
- iOS Safari需COOP/COEP头

### 6.2 adapter-taro（二期）

**微信小程序**：
- `wx.getRecorderManager()`，frameSize:8 (~80ms@16k)
- 无AudioWorklet → 主线程WASM重采样
- 无 `AudioContext.currentTime` → TTS用 `InnerAudioContext` 顺序队列

**文档化限制**（capability matrix）：
```typescript
const capabilities = {
  hasAudioWorklet: false,
  hasSAB: false,
  hasTimeScheduling: false
};
```

### 6.3 adapter-electron

**复用adapter-web + 增强**：
- 原生菜单栏桥接
- `desktopCapturer` 系统音频采集
- IPC桥：重WASM跑在隐藏BrowserWindow的Worker

## 七、技术深度亮点（12条）

### L1 核心层

1. **四路径增量转写去重Reducer**（514行纯函数）
   - 处理累积/增量/混合模式、乱序partial、终结后修正
   - fast-check属性测试验证幂等

2. **Volcengine v3/sauc二进制协议编解码器**
   - 凭抓包+Python源码TS重写
   - 黄金fixture测试覆盖

3. **chunk_id → RTT HDR Histogram观测协议**
   - 对数线性桶3位有效数字
   - p99误差≤1%

4. **WebSocket会话恢复协议**
   - 抖动指数退避
   - resumeToken + lastServerSeq

### L2 适配器层

5. **AudioWorklet + SharedArrayBuffer零拷贝环形缓冲**
   - `Atomics.wait/notify` 同步
   - 主线程100%负载下稳定20ms帧

6. **时间调度的AudioContext播放队列**
   - `source.start(atTime)` + 漂移补偿
   - 暴露 `getScheduledEndTime`

7. **Speex/多相Sinc WASM重采样器**
   - Kaiser窗设计、保相位
   - 替代线性插值的混叠

### L3 场景层

8. **responseId门控的Barge-in状态机**
   - 跨队列/解码/播放三阶段原子中断
   - 附TLA+形式化规约

9. **卡拉OK词索引二分 + rAF节流对齐**
   - O(log n)查找
   - 16ms leading + trailing节流

10. **Opus WASM自适应码率编码**
    - 按RTT p95驱动（4G 8k / WiFi 24k）

### L4 框架层

11. **IndexedDB持久的离线文件转写队列**
    - 重载恢复 + Web Worker执行

12. **三端跨端抽象**
    - IAudioCapture/IAudioPlayer/ITransport接口契约
    - 同一套状态机零修改复用
