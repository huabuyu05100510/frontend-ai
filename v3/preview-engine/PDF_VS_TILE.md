# PDF 方案 vs Tile 渲染方案对比
> 日期：2026-06-18

---

## 核心区别一句话

> **PDF 是"死"的，Tile 是"活"的。**

```
DOCX → PDF → pdf.js 渲染
              ↑
         文档结构已丢失，只剩像素描述，无法再编辑

DOCX → LibreOffice 进程（持续运行）→ Tile 渲染
              ↑
         文档结构还活着，可继续编辑，改一个字只重渲染脏 tile
```

---

## 五个维度对比

### 1. 编辑能力（最根本）

```
PDF 方案：
  用户改一个字 → 无法改 PDF → 需要反向转回 DOCX → 再转 PDF → 重渲染
  round-trip 有损且慢，根本不可行

Tile 方案：
  用户改一个字 → 服务端 LibreOffice 直接应用修改
               → 只重渲染受影响的 2-3 个 tile
               → WebSocket 推送差量 tile
               → 延迟 50-100ms，实时感
```

### 2. 实时协同

```
PDF 方案：无解。PDF 是终态格式，没有"多人操作同一 PDF"的机制。

Tile 方案：
  服务端维护 1 个 LibreOffice 实例（文档始终打开）
  用户 A 的操作 → 更新文档状态 → 重渲染脏 tile → 推送给所有人
  天然支持多人实时协同
```

### 3. 增量更新效率

```
修改了第 3 页第 2 段：

PDF 方案：一页 PDF ≈ 50-200KB，即使增量也要重新序列化整页
Tile 方案：只有覆盖该段落的 2-3 个 tile 脏掉，每个 256×256 tile ≈ 5-15KB
           推送量减少 10-20 倍
```

### 4. 大文档按需加载

```
500 页文档：

PDF 方案（非线性化）：必须下载完整 PDF 结构才能渲染任意页
Tile 方案：只渲染当前视口的 tile，内存和带宽始终只有"一屏"的量
```

### 5. 交互元素

```
PDF 方案：超链接/表单转为 PDF 注解格式，能力取决于 pdf.js 支持度
Tile 方案：服务端单独提供"交互热区"JSON，完整保留原始文档交互语义
```

## 汇总对比表

| | PDF 方案 | Tile 方案 |
|---|---|---|
| 只读预览 | ✅ 够用且简单 | 过度设计 |
| 内容编辑 | ❌ 根本不行 | ✅ |
| 实时协同 | ❌ | ✅ |
| 大文档流式加载 | ⚠️ 需线性化 | ✅ |
| 架构复杂度 | 低 | 高 |
| 服务端依赖 | 转换时一次性 | 持续运行 LibreOffice 进程 |
| 首屏延迟 | 3-8s（转换）| 1-2s（增量传瓦片）|

## 文字层复制的实现（两方案相同）

两方案都使用"视觉层 + 透明文字层"叠加架构，复制走文字层：

```
┌──────────────────────────────────┐
│  文字层（透明但可选中）z-index:1  │  ← 负责选中/复制/搜索/无障碍
│  <span color:transparent         │
│    position:absolute 匹配字形坐标>│
├──────────────────────────────────┤
│  视觉层（Canvas/PNG）z-index:0    │  ← 负责视觉显示
└──────────────────────────────────┘
```

PDF.js 方案（本项目 PdfEditor.tsx 已有）：
- pdf.js `getTextContent()` → 字符坐标 JSON
- `renderTextLayer()` → 自动生成透明 span

Tile 方案：
- LOKit `getTextLayout()` C++ API → 字符坐标 JSON（服务端提供）
- 客户端手动构建透明 span 覆盖层
- 逻辑与 PDF.js 文字层完全一致，可复用 `.textLayer` CSS

## 本项目的选型结论 --临时方案

**preview-engine 定位**：文档预览 + 协同批注（非重度内容编辑）

```
当前实现（已有）：
  PDF 文件 → pdf.js 渲染 → 可复制 + 可批注 ✅

扩展计划：
  DOCX/XLSX/PPTX → 后端 LibreOffice 转 PDF → pdf.js 渲染 → 可复制 + 可批注
  （无需实现 Tile 方案，PDF 路线对预览场景性价比更高）

未来（如需编辑）：
  引入 Collabora Online 开源版（Tile 方案）
```
